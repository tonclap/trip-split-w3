# Этап 2 — наш инструмент на наборе Максима

Набор: [`github.com/baramba/trip-settle-tbilisi`](https://github.com/baramba/trip-settle-tbilisi)
(Тбилиси, 3–6 сентября 2026, пятеро: Аня, Борис, Вера, Глеб, Ира; 12 чеков, 2 возврата,
₽ и ₾ по курсу на дату). Прогон 30.09.2026. Полный вывод всех прогонов — [`run0.txt`](run0.txt).

## Оговорка честности, до результатов

Пять контрольных фактов Максима напечатаны **открытым текстом в его `README.md`**
(раздел «Как это делалось», пункт 1), и я прочитал их раньше, чем прогнал расчёт.
Слепым этот прогон не был. Совпадение ниже доказывает, что расчёт не противоречит
эталону, но не доказывает, что он получен независимо от него. Его `facts.md`,
`report.md` и `settle.py` не открывались.

## Что сломалось

### 1. Инструмента без правок не существует: у него нет входа

`split.py` не читает данные **вообще**. `PEOPLE`, `RATE`, `LEDGER` и `MONEY_MOVES` —
константы в теле файла (строки 25–57); каталог `data/` читает только `verify.py`,
и только для сверки. Формально «прогнать без правок под чужой набор» невозможно:
чужой набор инструменту некуда подать.

### 2. Худшее: на чужом наборе он зелёный

Прогон `run0b` — `split.py` запущен как есть, данные Максима лежат в соседней папке:

```
Оля         24 829.20    12 078.73    12 750.47
...
проверки пройдены: балансы, котёл, план переводов и число переводов
совпали с эталоном facts.md; после плана у каждого ноль        exit=0
```

Он напечатал **наши** числа (Оля, Макс, Тимур, Лера, Сева) и объявил проверки
пройденными, тогда как на входе был набор про Аню, Бориса, Веру, Глеба и Иру.
Это не «упал и не посчитал» — это уверенный неверный ответ с зелёным статусом.
Ведущий нашёл у себя две ложнозелёные проверки из четырнадцати; у нас ложнозелёный
весь прогон целиком, потому что данные и эталон зашиты в один и тот же репозиторий.

### 3. `verify.py` не запускается

```
FileNotFoundError: ...\stage2\maxim-tbilisi\data\chat.md
```

Он жёстко ждёт `data/chat.md` и `data/receipts/R*.txt` — по файлу на чек. У Максима
чеки лежат структурой внутри `data.json`, отдельных файлов нет. Половина нашей
проверочной машинерии на чужом формате не работает в принципе.

### 4. Модель расходится с чужой в трёх местах

| Что | У нас | У него | Чем закрыто |
|---|---|---|---|
| Курс | один на поездку (`RATE = 34.20`) | четыре, по дате чека | пересчёт в рубли по дате в `adapt.py`, в модуль отдан `RATE = 1.0` |
| Возврат | понятия нет; `MONEY_MOVES` — передача между участниками | `refunds` от продавца по чеку | отрицательная строка реестра с составом дележа исходного чека |
| Спорное | в отчёте прозой | поле `disputed` в данных | перенесено в отчёт списком, в расчёт не идёт |

## Сколько ручных правок понадобилось

- **Правок в `split.py` и `verify.py` — 0.** `split.py` импортирован как модуль,
  константы подменены снаружи ([`adapt.py`](adapt.py)); файл не тронут.
- **Правок в данных Максима — 0.** `data.json` взят как есть.
- **Написано нового кода — 110 строк** адаптера. Это и есть честная цена: правок
  нет не потому, что инструмент универсален, а потому что переходник пришлось
  написать целиком.

## Порча входа против проверок (канон `testing_standard.md` §7.1)

На чужом наборе эталона в нашем формате нет, поэтому из `check()` остаются только
проверки, которым эталон не нужен. [`corrupt.py`](corrupt.py) портит вход семью
способами:

```
зелёная ← порча не поймана   сумма чека R01: 30 000 → 33 000
зелёная ← порча не поймана   плательщик чека подменён
зелёная ← порча не поймана   состав дележа: отсутствовавший возвращён
зелёная ← порча не поймана   знак возврата V01 перевёрнут
зелёная ← порча не поймана   курс на дату: 29,4 → 99,0
зелёная ← порча не поймана   последний чек удалён
зелёная ← порча не поймана   у чека R01 убран источник
поймано порч: 0 из 7
```

**0 из 7.** Причина структурная: без эталона в `check()` работают ровно четыре
проверки, и три из них не могут провалиться по построению — сумма балансов есть
Σ внесённого минус Σ долей, нулевое сальдо после плана и предел n−1 следуют из
самого жадного алгоритма. Ровно тот паттерн, что уже занесён в канон 29.09 по этому
же репозиторию, но здесь видно его настоящую цену: **вся защита набора держится на
`facts.md`, и за пределами своей поездки её нет**.

Седьмой случай — отдельный дефект, не тавтология: проверка «строка без источника»
смотрит `if not row[7]`, то есть на список, а не на его содержимое. Источник `[""]`
— непустой список, и проверка молчит. Это верно и для нашего собственного реестра.

## Спорное

Взято из его `disputed`, в расчёт не входит:

- **S1 (M26, повтор M38)** — Глеб: «за завтрак заплатил, чек скину потом». Сумма не
  названа, чека нет → ждём чек.
- **S2 (M31)** — Борис → Глебу: «за вино свою долю уже перевёл». Подтверждения от
  Глеба нет → доля Бориса в R09 остаётся.
- **S3 (M34–M36)** — 1 000 ₽ удержаны из депозита за разбитое стекло, виновник не
  назван → делится поровну на пятерых как часть R01: депозит вернулся на 4 000, а
  не на 5 000 ₽.

Своего, сверх его списка, я не нашёл: состав дележа у всех 12 чеков задан полем
`for` явно, каждый чек ссылается на существующее сообщение.

## Что из этого следует для нашего набора

1. **Завести вход.** Пока реестр — константа в теле `split.py`, инструмент
   одноразовый, а «прогон на чужих данных» невозможен без переходника.
2. **Починить проверку источника**: `if not row[7]` → проверять содержимое, а не
   список.
3. **Перестать считать `--check` доказательством.** Вне `facts.md` он не ловит
   ничего: 0 из 7. В README это сейчас описано мягче, чем есть на деле.

## Постскриптум 30.09.2026: все три находки закрыты

Отчёт выше описывает состояние инструмента **на момент обмена**. В тот же день все
три дефекта исправлены, и набор Максима теперь гоняется без переходника:

```bash
python split.py --data stage2/maxim-tbilisi/src/data.json           # расчёт
python split.py --data stage2/maxim-tbilisi/src/data.json --corrupt # порча входа
```

- **вход появился** (`--data`, схема — [`../../data/registry.schema.md`](../../data/registry.schema.md));
  формат Максима читается как есть, включая `source` одной строкой и курсы по датам;
- **проверка источника** смотрит на содержимое списка, а не на его пустоту (`[""]` ловится);
- **зелёный прогон больше не пустой**: структурные проверки отделены от эталонных, на
  этом наборе **краснеет 5 порч из 8** вместо 0 из 7, а три непойманных (сумма, плательщик,
  урезанный состав) печатаются как граница инструмента, а не умалчиваются.

Приёмочный набор этапа 3 добавил четвёртую находку: `round(value / len(share), 2)` на
шести участниках давал остаток −0,08 ₽, из-за которого инвариант «сумма балансов = 0»
краснел на **верном** расчёте. Деление теперь точное, до копейки.

`corrupt.py` в этой папке трогать не стали: он держит собственную копию проверок
**на момент обмена** и остаётся свидетельством «0 из 7». Текущее состояние показывает
`split.py --corrupt`, а не он.
